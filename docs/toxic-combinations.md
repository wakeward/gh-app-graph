# Toxic permission combinations

Generated by `cmd/build`.

## Arbitrary Code Execution (Critical)

- **ID:** `arbitrary-code-execution`
- **Permissions:** `workflows:write` + `contents:write`
- **Risk:** Workflows: write allows the app to create or modify GitHub Actions YAML files in the .github/workflows/ directory.

**Exploit path:** The attacker pushes a malicious workflow file that executes arbitrary shell commands on the GitHub-hosted runner. Because the workflow runs in the context of the repository, the attacker can use this compute environment to exfiltrate environment variables, access cloud provider credentials, or launch attacks against internal infrastructure.

## Organization Takeover (Critical)

- **ID:** `organization-takeover`
- **Permissions:** `organization_administration:write` + `members:write`
- **Risk:** Organization administration and Members write together enable promoting attacker accounts to Org Owner and locking out legitimate admins.

**Exploit path:** Promote an attacker-controlled account to Org Owner, then demote or remove legitimate admins.

## Status Check Forgery Merge (High)

- **ID:** `status-check-forgery-merge`
- **Permissions:** `checks:write` + `pull_requests:write`
- **Risk:** Checks: write can forge required status results; Pull requests: write can open and merge changes without human review when combined.

**Exploit path:** Create a pull request, mark required checks as passed via the Checks API, and merge without legitimate CI or human approval.

## Stealth Backdoor (Critical)

- **ID:** `stealth-backdoor`
- **Permissions:** `administration:write` + `contents:write`
- **Risk:** Administration: write allows the app to manage repository settings, including branch protection rules

**Exploit path:** An attacker can use the App to temporarily delete branch protection rules (like "require pull request reviews" or "require status checks"), push malicious code directly to the main branch using Contents: write, and then re-enable the protection rules. This allows them to inject backdoors into production code entirely undetected by standard developer workflows.

## Supply Chain Poisoning via Releases (High)

- **ID:** `supply-chain-poisoning-via-releases-deployments`
- **Permissions:** `contents:write` + `deployments:write`
- **Risk:** Allows an attacker to manipulate the final artifacts delivered to customers, bypassing the actual source code.

**Exploit path:** Instead of modifying the source code (which might be audited), the attacker waits for a legitimate build to complete, then uses the App to overwrite the release artifact (e.g., an npm package, a Docker image, or a compiled binary) with a maliciously compiled version.
